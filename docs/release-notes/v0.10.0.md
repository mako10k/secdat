# secdat v0.10.0 Release Notes

## Highlights

- v2 key removal, replacement, linking, and move operations now commit only
  their bounded namespace and deferred-GC topology writes. Foreground mutations
  no longer scan registered domains to prove reference counts and no longer
  physically delete unreferenced secret objects.
- Deferred-GC candidates are durable, canonical records in the owner-domain
  queue. Reference additions cancel stale candidates in the same transaction;
  removals enqueue a fresh generation and update the cached refcount hint.
- The session agent advertises `GC_WORKER_V1`, accepts exact `GCWAKE` requests,
  and processes bounded batches. Collection uses an owner lease, a nonblocking
  mutation fence, reference-epoch and candidate-generation fences, and an
  authoritative scan across physical domain entries before deletion.

## Recovery and administration

- Agent startup, wake notifications, and timer polling resume queued work after
  process or host interruption. Incremental scans service the agent socket
  while retaining directory cursors and stop each automatic slice after at
  most eight selected candidates or 100 ms.
- Retry state uses persisted backoff and promotes repeated failures to
  `manual-required`. `gc --status`, JSON/error output, owner selection,
  quarantine/drop operations, and `secret status --gc` expose the lifecycle
  without treating cached counts as deletion authority.
- `gc --queued` runs the same proof path manually. Legacy orphan collection
  converts valid objects into candidates before deletion, and store/domain
  deletion refuses owners with pending or quarantined GC work.

## Compatibility

- Existing v1 data and CLI behavior remain supported. Candidate parsing is
  strict and fail-closed; corrupt records are reported and can be quarantined
  explicitly.
- The public C SDK ABI and `libsecdat.so.0` SONAME are unchanged from v0.9.0.
  Python, Rust, and Node binding package versions track `0.10.0`; the Rust
  binding requires `libsecdat >= 0.10.0` through `pkg-config`.

## Validation

- Regression coverage includes crash recovery, candidate generation and
  cancellation, shared links, unregistered physical cross-domain references,
  corrupt/quarantine handling, agent handover, automatic collection, bounded
  socket servicing, read-only/volatile retention, migration, and v2 fsck.
- Release validation includes gettext freshness, metadata and ABI checks,
  jscpd/lizard static analysis, the complete regression matrix, FUSE-enabled
  default/shared-only/static-only distcheck profiles, and installed C, Python,
  Rust, Node, and Go consumers.
