# secdat v0.8.0 Release Notes

## Highlights

- Persistent v2 mutations now have a guarded transaction-manifest contract
  that separates validation-only guards from replayable writes and gives each
  write a semantic role and deterministic publication phase.
- `fsck --format v2 --dependency-index [--repair]` adds a strict global reverse
  dependency index for identity masks, relation members, and relation domains.
  Missing, building, corrupt, or stale coverage fails closed instead of being
  interpreted as an empty dependency set.
- Relation-dependent hidden-name transitions use exact reverse lookup without a
  registered-domain scan fallback. Dependency nodes are immutable,
  content-addressed, bounded, and do not contain plaintext hidden key names or
  KEYREFs.

## Compatibility and operations

- The new dependency-index command is additive. Existing v1 behavior and the
  public C SDK ABI are unchanged from v0.7.0.
- Current canonical mask and relation writers invalidate a complete dependency
  generation before changing a primary. Run
  `fsck --format v2 --dependency-index --repair` before a reverse-dependent
  hidden-name operation after those mutations.
- Until atomic mask-primary rewriting is routed, an identity-mask dependency
  rejects either key-visibility transition. Updates that keep the existing
  visibility continue to work.
- Transaction manifest v1 remains readable for recovery compatibility. New
  transactions use the stricter v2 manifest shape and bounded blob accounting.

## SDK and bindings

- Python, Rust, and Node binding package versions track the core release at
  `0.8.0`; the Rust binding requires `libsecdat >= 0.8.0` through `pkg-config`.
- No public SDK symbol or SONAME change is included in this release.

## Validation

- Regression coverage includes exact-file guard parsing and recovery,
  deterministic write ordering, dependency-state and node corruption,
  M/R/D coverage, stale-primary detection, symlink rejection, hidden-name
  non-disclosure, relation and mask transition guards, SDK consumers, and FUSE
  fixtures.
