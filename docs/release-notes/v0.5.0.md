# secdat v0.5.0 Release Notes

## Highlights

- Adds per-key ephemeral secrets backed only by the active session agent. They
  participate in normal reads, explicit `exec` injection, SDK and FUSE reads,
  while retaining independent bulk-selection attributes and never being saved
  to the persistent store.
- Adds capability-negotiated, lossless session-agent handover. Persistent,
  readonly, and volatile session state, overlay tombstones, and per-key
  ephemeral values can move to a replacement agent without extending expiry or
  writing handover plaintext to disk.
- Adds identity-aware mask inspection and mutation planning for v2 stores,
  including recoverable mask writes, migration planning, and structured impact
  reporting.
- Extends `exec` with command-scoped injection profiles and stable plan identity
  fields, backed by shared redaction classification and relation-refresh
  suggestions for integrations.

## SDK and bindings

- The C SDK adds preserve-attribute write/resize operations, exec-plan JSON,
  redaction classification, and relation-refresh suggestion APIs.
- The Python and Go bindings expose the new exec-plan, redaction, and
  relation-refresh surfaces.
- Static-only Go consumers can opt in to the private native dependency closure
  with the `secdat_static` build tag; normal Go builds retain the shared-library
  contract.
- The Rust and Node packages continue to expose their established binding
  surfaces in this release; they track the core package version but do not yet
  wrap every new C SDK operation.
- The C ABI additions are backward compatible. Libtool version-info advances to
  `1:0:1` while the shared-library SONAME remains `libsecdat.so.0`.

## Reliability and compatibility

- Mixed-version session agents are negotiated explicitly. Unsupported or
  malformed negotiated operations fail with actionable diagnostics instead of
  silently discarding active state or returning partial status data.
- Handover phases are bounded and secret-bearing transfer buffers are cleared
  on both success and failure paths.
- Effective key enumeration now applies the same ephemeral-overlay precedence
  as direct lookup across CLI, SDK, exec/export, FUSE, status, and save guards.
- CLI and FUSE build identifiers now follow HEAD and clean/dirty transitions in
  incremental builds, preventing stale provenance from being installed.
- Warning-clean builds and timing-sensitive SDK/session regressions have been
  hardened for full-suite execution.

## Validation

- The release is validated with the FUSE-enabled full regression suite and
  `make distcheck`.
- Installed-consumer checks cover pkg-config, Python wheel/import, Rust
  check/package, Node build/packed install, and Go build.
- ABI validation checks the retained v0.4.2 SDK exports and the
  `libsecdat.so.0` SONAME.

## Versions

- The C project version is `0.5.0`.
- Python, Rust, and Node binding package versions track `0.5.0`.
- The Rust binding requires `libsecdat >= 0.5.0` through `pkg-config`.
