# secdat v0.7.0 Release Notes

## Highlights

- Domain-qualified KEYREFs now target only the named registered domain. An
  absolute reference such as `/project/child/API_TOKEN` no longer falls back
  to a same-name key in a parent domain.
- KEYREF domain qualifiers may now be relative. Their base is `--domain`, then
  `--dir`, then the current working directory, so operations such as
  `secdat mv ../SOMEKEY ./SOMEKEY` address exact parent and child key slots.
- Bash completion resolves relative and absolute qualified domains, offers
  exact-local key and store candidates, and carries a source key name into an
  available `cp`, `mv`, or `ln` destination qualifier.

## Compatibility

- Exact-local behavior for an already-supported absolute domain qualifier is
  a correctness fix: an explicit domain must not silently select an ancestor
  entry. Because a script may nevertheless have relied on the old fallback,
  this release uses a minor version bump rather than a patch version bump.
- To retain inherited lookup, remove the domain path from the KEYREF and select
  the current context with `--domain` or `--dir`. Path-qualified references are
  always exact-local, while unqualified keys retain the existing inheritance
  chain.
- Domain paths retain the existing real-path and root-identity validation. A
  symlink alias to an intact registered root is accepted; broken aliases,
  non-root paths, and replaced registered roots fail closed.
- The store formats and public C ABI are unchanged from v0.6.1.

## SDK and bindings

- CLI and C SDK calls share the same relative-path and exact-local KEYREF
  parser and lookup contract.
- Python, Rust, and Node binding package versions track the core release at
  `0.7.0`; the Rust binding requires `libsecdat >= 0.7.0` through `pkg-config`.

## Validation

- Regression coverage includes v1 and v2 relative moves, absolute and relative
  exact-local reads, `--domain`/`--dir`/cwd bases, masks and removals, SDK
  lookup, store suffix completion, and valid, broken, and identity-mismatched
  symlink paths.
