# secdat v0.9.0 Release Notes

## Highlights

- Persistent v2 mutations now derive bounded exact write sets and publish them
  directly through the shared recovery journal. Normal mutation preparation no
  longer clones and diffs a complete store tree. Non-destructive mutation
  dependency discovery no longer scans unrelated registered domains; the
  documented destructive actual-reference compatibility branch remains until
  ADR 0008 deferred GC.
- `mv` preserves both entry and secret UUIDs. Same-owner moves keep the current
  reference epoch; cross-owner moves publish the destination, rotate the epoch,
  and only then remove the source.
- Store/domain create, delete, and move are guarded container transactions.
  Create/delete accept only a canonical empty `CONTAINER_TREE`, while unknown
  or data-bearing artifacts fail closed.

## Recovery and dependency safety

- The command-wide mutation lock now covers recovery, authoritative plan
  construction, and commit, closing the recovery-before-builder race window.
- Transaction manifest v2 records semantic roles, deterministic phases, exact
  guards, and bounded file or container images. Version-1 manifests remain
  readable for recovery compatibility.
- Mask, relation, metadata, attribute, key, batch, and topology mutations update
  only affected dependency-index paths. Visibility changes preserve canonical
  mask closure, and relation-domain dependencies move atomically with domains.
- Topology-changing store/domain operations durably rotate the reference epoch
  before publication, unpublication, or source removal.

## Compatibility

- Existing v1 behavior and the public C SDK ABI/SONAME remain unchanged from
  v0.8.0. Python, Rust, and Node binding package versions track `0.9.0`; the
  Rust binding requires `libsecdat >= 0.9.0` through `pkg-config`.
- Legacy generic staging directories are accepted only for bounded recovery
  cleanup; new normal mutations never create them.

## Validation

- Regression coverage includes every transaction recovery boundary, UUID-stable
  same/cross-owner moves, container publication/removal, epoch ordering,
  dependency-index consistency, hidden names, masks and links, batch operations,
  unrelated-domain sentinel guards, and FUSE/SDK consumers.
- Structural `strace` counts are identical with one and one hundred registered
  domains. The order-rotated performance acceptance requires the 100-domain
  median to remain within 1.25x of the one-domain median.
