# secdat v0.6.1 Release Notes

## Highlights

- Persisted v2 `set` now prepares and commits only the exact entry, object,
  compatibility tombstone, and legacy-value paths affected by the operation.
  It no longer clones, fsyncs, diffs, and removes the complete persisted
  secdat state tree for each value update.
- Repeated assignments in one `set` invocation observe earlier projected
  writes while retaining one atomic transaction and the final value.
- Existing mask planning, dry-run/reject output, link-alias object updates,
  and crash roll-forward behavior remain covered by the same transaction
  contract.

## Performance

- In an order-rotated comparison with five warm-up runs and twenty measured
  runs per case, increasing from one to twenty unrelated domains changed the
  median `set` time by 5.439x before this fix and 1.046x after it.
- A separate 100-domain syscall trace opened only the selected domain's
  `by-id` tree, opened no unrelated domain, and created no legacy staging
  directory. Absolute latency remains dependent on journal fsync behavior;
  the structural non-traversal result is the compatibility gate.

## Compatibility and scope

- The command-line interface, store formats, transaction recovery contract,
  and public C ABI are unchanged from v0.6.0.
- This release changes the persisted v2 `set` path only. Scoped preparation
  for `cp`, `ln`, `rm`, and `load`, deferred object GC, and lifecycle
  timestamps remain tracked follow-up work and are not enabled here.
- The same-protocol session-agent handover limitation remains tracked as
  known issue #221.

## SDK and bindings

- Python, Rust, and Node binding package versions track the core release at
  `0.6.1`; the Rust binding requires `libsecdat >= 0.6.1` through
  `pkg-config`.

## Validation

- The release candidate is checked with the FUSE-enabled default,
  shared-only, and static-only distribution profiles, plus installed C and
  language-binding consumer checks.
